Quberi 中文

An AI knowledge base where permissions are per document

Permissions in Quberi are per document, not per space. Within one space, two users can see different documents. A deny rule wins over any allow rule or space role, retrieval is filtered inside the vector index, and rules are evaluated on every request, so a change applies to the next one.

Quberi is an AI knowledge base for teams that can also be used by AI agents. Most tools stop at "can this person enter this space". In Quberi the question is asked of each document: people who can read the space, plus people who were given access to one document, minus people who were denied that document. Denied wins over everything. Two people can ask the same question in the same space and get different answers, because they are allowed to see different documents.

Filtered inside retrieval, not after it

Permission filtering happens inside the vector index. A denied document is never a candidate, so you do not get the top ten results with three holes cut out of them. The result is checked again before it is returned. Rules live in the database and are read on every request, so nothing is cached per person, and a preview link issued before access was removed stops working on the next request.

Answers with citations, and a check before sending

Answers carry citations that show which documents they came from. Before a question and the retrieved passages go to the chat model, you can preview them, edit them, or drop individual passages. Admins get an audit log of sensitive actions, including searches made by connected outside tools, so the question "what could the model see?" has an answer.

Use it from an AI agent

Quberi can be a knowledge source for outside tools. An organization admin can allow read-only search through OAuth, which is off by default. A plugin for DeepSeek Harness is published as dsh-quberi. The agent acts as the person who approved it, so it finds exactly the documents that person can read. Changing tools does not widen access.

Who it is for

Teams whose documents share a space but not an audience: customer drawings, technical agreements, quotations and employee handbooks. Space-level permissions cannot tell them apart. Document-level permissions can.

Sign-in and deployment

Sign-in is by email code, Google or Feishu. Every organisation's identity system is different, so Quberi adapts sign-in to each customer's actual needs. Use Quberi's cloud, or host it yourself with Docker Compose (the code is open source). For engineering drawings, add a text description when you upload (drawing number, model) to make them easier to find.
