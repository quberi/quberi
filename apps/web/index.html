企业 AI 知识库，权限做到单份文档

Quberi 的权限粒度是单份文档（document-level），不是空间（space）。 同一个空间里，不同的人能看到不同的文档。拒绝优先于允许，检索时在向量索引内部过滤， 权限规则在每一次请求时实时判断。

Quberi 是一个可以接给 AI Agent 使用的企业知识库。和常见做法不同的是， 权限不是“能不能进这个空间”，而是单份文档：能读空间的人， 加上被单独授权的人，减去被单独拒绝的人，拒绝优先于一切。 同一个知识库里，不同的人看到的文档、搜到的结果、得到的 AI 回答都可以不一样。

检索时会在向量索引内部完成权限过滤，所以你不会拿到“十条里挖掉三个洞” 的结果；已经发出去的预览链接，在权限撤销后下一次请求就会失效。

对管理者来说，这意味着可以放心地把一个人加进空间，再把其中几份文档单独对他关上； 对使用者来说，AI 给出的每一个回答，都只建立在他本人有权阅读的资料之上。 权限规则只有一套，网页对话、预览链接和外部 Agent 都遵守同一套。

回答有出处，发送前可检查

Quberi 的 AI 回答会附带引用，告诉你答案来自哪几份文档。在内容发送给大模型之前， 用户可以检查并修改将要发送的文档片段，不想让模型看到的内容可以先拿掉。 管理员可以在审计日志里看到每一次提问、模型能够看到哪些文档，以及空间、成员和文档权限的变更记录， 出了问题能追溯，而不是只能相信“应该没问题”。

接入 AI Agent

除了网页端的对话，Quberi 也可以作为外部 AI Agent 的知识来源： 支持 DeepSeek Harness 插件，也支持通过 MCP 接入其他 Agent。 Agent 以用户的身份、经过用户授权后检索知识库， 因此它能查到的文档，和这位用户本人能查到的完全一致，不会因为换了入口而放宽权限。

适合什么场景

制造业、能源、合规密集型企业：客户图纸、技术协议、报价单和员工手册 往往在同一个知识库里，但受众完全不同。空间级权限做不到区分， 文档级权限可以。销售能看到报价单但看不到客户的技术协议， 工程师能查到图纸但看不到价格。

已知限制

目前没有飞书之外的内置 SSO，Quberi 更愿意按客户的实际需求改造登录方式；图片检索对工程图纸不敏感；跨组织共享未验证。 我们把这些写在文档里，而不是藏起来。
